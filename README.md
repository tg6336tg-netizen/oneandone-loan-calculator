# 원앤원 부동산 담보대출 한도 계산기

React · TypeScript · Vite 기반 웹 프로젝트입니다. 별도 서버, API 키, 데이터베이스 없이 실행합니다.

## 개발 환경

- Node.js 22.12 이상(22.x) 또는 24 이상. 검증 환경: Node.js 24.19.0 / npm 11.9.0
- `.npmrc`는 프로젝트 안의 `.npm-cache/`를 사용하므로 클라우드와 로컬 모두 별도의 전역 캐시 설정 없이 설치할 수 있습니다. 이 폴더는 Git에서 제외합니다.

```bash
npm install
npm run dev -- --host 0.0.0.0
```

이후 재설치와 CI에서는 잠금 파일을 사용하는 `npm ci`를 권장합니다.

## 검증 및 빌드

```bash
npm run lint
npm run build
npm run preview -- --host 0.0.0.0
```

`build`는 TypeScript 검사 후 정적 배포 파일을 `dist/`에 생성합니다. `preview`는 빌드 결과의 로컬 검증 용도입니다.

## 내부 검토용 계산 기준

사용자가 제공한 내부 기준을 반영합니다. 계산 결과는 내부 검토용이며 실제 대출 승인은 별도 심사가 필요합니다.

| 담보 유형 / 지역 | LTV |
| --- | --- |
| 서울 아파트 | 72% |
| 서울 제외 전국 아파트 | 68% |
| 수도권 빌라 (서울·경기·인천) | 50% |

명시되지 않은 유형(예: 수도권 외 빌라)은 지원하지 않습니다.

- 신용점수 600점 이상(입력 범위 0~1000점). 미달이면 한도 0원, 월 이자 산정 제외.
- 기본 연금리 18% 고정.
- 예상 추가 한도 = max(0, 담보가액 × LTV / 100 − 선택한 선순위 금액).
- 원금 기준이 기본이며, 채권최고액 기준을 선택하면 등기상 채권최고액을 직접 입력합니다. 임의 배율을 적용하거나 원금과 중복 차감하지 않습니다.
- 차감 기준 변경 시 금액을 비워 다른 기준의 금액을 재사용하지 않도록 합니다.
- 금액은 정수 만원 단위(담보가액 1~100,000,000만원, 선순위 금액 0~100,000,000만원)로 입력하고 결과는 원 단위로 표시합니다.
- 월 이자 = 추가 대출 한도 × 18% ÷ 12. 원 단위 반올림, 한도 전액 사용 가정, 원금 상환액 제외.
- 기본 예: 서울 아파트 5억원, 선순위 원금 1억원, 신용점수 600점 → 추가 한도 2억 6천만원, 월 이자 390만원.
- 입력 변경 시 이전 결과를 초기화합니다. 입력 정보는 저장하거나 외부로 전송하지 않습니다.

## 등기부등본 PDF 분석 (Issue #3)

PDF 업로드 → 브라우저에서 PDF.js 텍스트 추출 → 텍스트가 없는 페이지에 Tesseract.js 한국어/영어 OCR → 권리 검토 → 승인한 선순위 채권최고액을 계산기에 반영합니다. 기존 계산기 수동 입력은 그대로 사용할 수 있습니다.

### 검토 절차

1. 25MB·30페이지 이하 PDF를 선택합니다. 원본 PDF 링크와 페이지별 추출 원문을 대조합니다.
2. 권리별 갑구/을구, 순위번호, 목적, 접수일자/번호, 권리자, 채권최고액(원), 연결 대상 순위, 근거 문구·페이지를 확인·수정합니다. 누락된 권리는 수동 추가합니다. OCR 점수는 문자 인식 점수로 법적 정확도/심사 신뢰도가 아닙니다.
3. 근저당 이전은 대상 권리에 연결하고 중복 합산하지 않습니다. 전부말소는 대상이 하나로 연결되고 사용자가 전부말소임을 확인·승인한 경우에만 원 권리를 제외합니다. 일부말소를 자동 전부말소로 처리하지 않습니다.
4. 변경·감액·증액·일부말소는 자동 적용하지 않습니다. 원 권리의 현재 금액을 원문에 따라 수정·확인하고 변경 이력은 제외 승인합니다. 복수 대상·중복 순위·부기등기·공동담보는 수동 정리합니다. 공동담보목록은 경고와 원문으로 표시하며 목록 내 여러 부동산을 채권 수로 간주하지 않습니다.
5. 신규 대출의 을구 주등기 예정 순위를 입력합니다. 그보다 앞선 근저당만 합산합니다. 동순위 또는 부기 순위의 법적 선후관계는 자동 판단하지 않습니다.
6. 모든 권리의 확인/제외를 승인하고 전체 페이지·누락·중복·갑구 위험·등기 외 위험 검토를 체크해야 반영 버튼이 활성화됩니다. 반영 시 계산기는 채권최고액 모드로 바뀝니다. 원 단위 정확도를 유지하기 위해 선순위 입력은 만원 소수 넷째 자리까지 지원합니다. 반영 후 직접 수정·재계산할 수 있고 분석 검토 내용을 바꾸면 이전 반영값은 초기화됩니다.

등기상 채권최고액은 실제 원금이 아닙니다. 압류·가압류·가처분·경매개시결정은 위험권리로 표시하고, 임차인·보증금·세금 등 등기 외 위험은 별도 검토해야 합니다. 결과는 내부 검토용이며 실제 대출 승인은 별도 심사가 필요합니다.

### 개인정보 보호와 로컬 자산

- 파일과 추출 텍스트는 브라우저 메모리에서만 처리합니다. 외부 API, OCR 서버, CDN으로 전송하지 않습니다. localStorage/sessionStorage/IndexedDB에 문서를 쓰지 않습니다. OCR 언어 캐시도 비활성화합니다.
- PDF 원본은 브라우저 object URL로만 열고 교체·초기화·화면 해제 시 해제합니다. 분석 취소/초기화로 진행 중 작업을 중단할 수 있습니다. 원본 파일명·내용을 애플리케이션 로그로 기록하지 않습니다.
- `predev`/`prebuild`가 npm 패키지에서 PDF.js worker·폰트·CMap·WASM과 Tesseract worker·WASM·언어 모델을 `public/analysis-assets/`에 복사합니다. 생성 자산(약 64MB)은 Git 제외 대상이며 Pages 배포 시 `dist/`에 포함됩니다. 런타임 요청은 같은 사이트 정적 자산에 한정됩니다. 정적 모델/라이브러리의 일반 HTTP 캐시와 문서 영구저장은 구별됩니다.
- 테스트는 합성 문서만 사용합니다. 자동 스크린샷·동영상·trace 기록은 비활성화했습니다. 실제 고객 등기부를 fixture·로그·PR에 첨부하지 마세요.

### 제한 및 수동 대체

규칙 기반 파서는 모든 등기 양식을 해석하는 법률 판단 시스템이 아닙니다. 표 셀 순서, 다단 문서, 기울어진 스캔, 취소선, 이미지와 텍스트가 섞인 페이지, 잘못된 텍스트 레이어, 여러 부동산이 합쳐진 문서에서 누락·오분류가 생길 수 있습니다. 페이지를 넘는 행은 자동 연결하지 않습니다. 한글로 적힌 금액이나 OCR의 O/0 혼동은 추측하지 않고 수동 확인을 요구합니다. 취소선만으로 말소 여부를 판단하지 않습니다. 여러 부동산 등기부는 파일을 분리해 검토하세요.

암호 PDF·손상 파일·OCR 실패 시 원본을 보며 수동 텍스트 입력 또는 권리 추가 기능을 사용하세요. 자동 합계는 권리 누락을 증명할 수 없으므로 전체 원문 검토를 생략할 수 없습니다. **실제 등기부 샘플은 제공되지 않았으며 실물 검증은 미완료입니다.** 운영 사용 전에 담당자의 실제 문서 대조 검증이 필요합니다.
